# Evaluate game

Restate the player action, immediate consequence, objective, and failure loop.
Evaluate the rules with theme and progression removed. Separate observed
playtest evidence from design hypotheses; never invent sessions or results.

## Compact scorecard

Score each row **1–5**: 1 = weak, 3 = plausible with a concrete risk, 5 = strong.
Use **?** where information is insufficient. Include a short reason and mark
its basis as observed or hypothesized. Use the same assumptions across concepts.

| Criterion | What earns a strong score? |
| --- | --- |
| Novelty | A distinctive player decision, not a familiar loop with a new skin |
| 5-second comprehension | A new player grasps the action and its consequence in five seconds |
| Immediate feel | The first action gives clear, satisfying, controllable feedback |
| Skill ceiling | Practice improves prediction, precision, planning, or expression |
| Emergent possibilities | A few rules combine into varied, discoverable situations |
| One-hand mobile suitability | Comfortable thumb reach, little occlusion, readable targets, forgiving input |
| <=2-day prototypeability | One developer can test the core fun in two days with placeholder assets |
| Visual distinctiveness | Recognizable silhouettes and motion communicate the mechanic on a small screen |

Ask explicitly: **Would this still be fun without progression/unlocks?**
Explain the answer in terms of repeated action and mastery. Do not let a high
average conceal a weak core loop, unreadable controls, or excessive scope.
Novelty is provisional unless relevant comparisons have been checked.

## Decision and next test

Return the scorecard, strongest opportunity, biggest risk, and one verdict:
**prototype**, **revise**, or **shelve**. For multiple concepts, rank them and
explain the decisive tradeoff rather than treating totals as proof of fun.

Propose the cheapest test that could change the verdict, with an observable
pass/fail criterion chosen before testing. For example: show an unfamiliar
player five seconds without explanation, then ask them to act and predict the
result; remove unlocks and observe whether they voluntarily retry. Test on a
phone when judging thumb comfort or responsiveness. If only a written concept
exists, identify what the prototype must establish before claiming validation.
